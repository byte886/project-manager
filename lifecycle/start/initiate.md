# 项目启动（Initiation）

> **回答的问题**：新项目怎么立项？目录怎么搭？写什么就算开工了？
> **达到什么效果**：第一步就有清晰目标和目录结构，不用边做边想"现在该干嘛"。

---

## 一、启动阶段在做什么

核心就两件事：
1. **写项目总纲**：一页纸说清"为什么做、做成什么样算成功、谁负责、什么时候做完"。
2. **立项决策**：想清楚值不值得做，然后正式开始。

### 什么时候走这个模块

- 脑子里冒出新方向，决定要认真做（不是顺手试试）。
- 想给散落的资料（聊天记录、收藏、笔记）正式立一个项目。
- **不用走**：一两天能做完、无长期归档需求的小任务。

---

## 二、启动步骤（SOP）

1. **想清楚再启动**：目标是什么？值不值得做？没想清楚先别启动。
2. **写一页"项目总纲"**（模板见第四节）：目标、截止日、成功标准（可量化）、当前状态、负责人。写不出来 = 还没想清楚。
   - **对外收费/商业类项目**，加写一页商业论证：为谁做、怎么赚钱、怎么算赢。纯内部提效/学习/自用处可跳过。
3. **定状态标签**：默认 `Active`；还在调研、没真正开工的先标 `To Be Started`。
4. **按目录模板建结构**（见第三节），在知识库或本地目录落地。
5. **写第一条决策记录**：把"为什么做这个项目、放弃了什么备选"放进决策记录目录。

---

## 三、推荐目录模板（双层结构）

> 所有项目都有**第一层（项目管理层）**；进入开发的工程项目再加**第二层（工程扩展层）**。纯调研/文档型项目不需要第二层。

### 第一层：项目管理层（所有项目必选）

```
📁 <项目名>/
├── 📄 00_项目总纲.md          ← 一页纸入口：目标/期限/成功标准/状态/负责人
├── 📁 01_结论与产出/          ← 最终交付物（报告/方案/文档）
├── 📁 02_决策记录/            ← 关键决策与理由
├── 📁 03_进行中的任务/        ← 任务状态、问题台账、进行中草稿
├── 📁 09_调研底稿与素材/      ← 原始资料、引用、截图、访谈、转写稿
└── 📄 99_复盘与退役总结.md    ← 完成后写（见收尾模块）
```

**根目录标配文件**：

```
├── 📄 README.md               ← 项目概览，给人看（目标/架构/快速开始）
├── 📄 AGENTS.md               ← AI操作手册（目录约定/禁止事项/恢复顺序）
├── 📄 PROFILE.md              ← 事实层（技术栈/数据来源/关键约定）
└── 📄 .gitignore              ← 忽略规则（数据、运行产物、依赖环境等）
```

> README给人看、AGENTS给AI看、PROFILE记事实，三者分离不重复。

**六个槽位的作用**：

| 槽位 | 作用 |
|---|---|
| `00_项目总纲` | 入口页，30秒看清项目是什么、到哪一步 |
| `01_结论与产出` | 只放最终结论，不和素材混 |
| `02_决策记录` | 记"为什么这么选"，以后回看不会忘 |
| `03_进行中的任务` | 当前在做的事，一眼看到待办 |
| `09_调研底稿与素材` | 原始素材层，和结论分离 |
| `99_复盘与退役总结` | 完成后写，不提前建空文档也行 |

### 第二层：工程扩展层（可选，进入开发时启用）

```
├── 📁 src/                    ← 源代码（按模块分目录）
├── 📁 config/                 ← 配置文件；密钥用本地配置覆盖、不入库
├── 📁 scripts/                ← 可执行脚本（下载/批量处理/运维）
├── 📁 tests/                  ← 测试
├── 📁 data/                   ← 数据（整体忽略，不入库）
│   ├── raw/                   ← 原始数据（只读，绝不修改）
│   ├── processed/             ← 处理后数据
│   └── _workspace/            ← 运行时过程件（可随时清理）
├── 📁 results/                ← 分析结果（忽略，或只入库摘要报告）
├── 📁 docs/                   ← 工程文档（工作流/需求/目录说明/文档地图）
│   ├── guides/                ← 操作类SOP
│   └── templates/             ← 过程件模板
├── 📁 decisions/              ← 决策记录（只增不改）
├── 📁 memory/                 ← 工程记忆（跨会话稳定结论）
├── 📄 CHANGELOG.md            ← 变更日志（可选，中大型项目建议加）
└── 📄 LICENSE                 ← 开源协议（可选，公开仓建议加）
```

**核心设计原则**：
- 数据分层：原始数据只读，过程件不污染成品
- 文档分层：技术文档和治理文档分开
- 一条信息只放一处，避免重复维护
- 配置与代码分离，密钥明文不入库

### 两种结构怎么选（不要并存）

| 项目类型 | 决策记录放哪 | 进度台账放哪 |
|---|---|---|
| **轻量项目**（纯调研/文档，无代码） | `02_决策记录/` | `03_进行中的任务/` |
| **工程项目**（有代码/数据/脚本） | 统一到 `decisions/` | 统一到活态台账目录 |

> **选一种就统一**，决策记录不要同时出现在两处。

## 四、项目总纲模板（一页纸）

```markdown
# 项目总纲 · <项目名>

> 最后更新：YYYY-MM-DD ｜ 状态：Active / On Hold / To Be Started

## 1. 一句话目标
<项目完成后，会变成什么样？>

## 2. 成功标准（可量化）
- [ ] <可验收的硬指标1>
- [ ] <可验收的硬指标2>
- [ ] <可验收的硬指标3>

## 3. 期限
- 立项：YYYY-MM-DD
- 计划完成：YYYY-MM-DD
- 关键里程碑：<M1 / M2 日期>

## 4. 当前状态
- 现在在做：<本周聚焦的1-3件事>
- 下一步：<下一个动作>
- 主要风险：<一句话>

## 5. 负责人与资源
- 负责人：<我 / 协作者>
- 预计时间投入：<每周X小时>
- 预算/工具订阅：<有就写，没有写无>

## 6. 快速链接
- 交付物：<01_结论与产出/>
- 决策记录：<02_决策记录/>
- 底稿：<09_调研底稿与素材/>
```

## 五、创建检查清单

### 所有项目（必选）

- [ ] 写一页项目总纲（目标/期限/成功标准/状态/负责人）
- [ ] 成功标准是**可量化**的（不是"做得好"，是"月PV 1万"）
- [ ] 六槽位目录按 00/01/02/03/09/99 建好
- [ ] 标配文件已创建：README、AGENTS、PROFILE、.gitignore
- [ ] 状态标签已打（Active / To Be Started）
- [ ] 命名用数字前缀法（`NN_名称`）
- [ ] 第一条决策记录已写（为什么做、放弃了什么备选）

### 工程项目（进入开发时加做）

- [ ] 工程扩展层目录已建：src、config、scripts、tests、data、docs
- [ ] data/ 已整体忽略（原始数据/处理后数据/过程件不入库）
- [ ] docs/ 骨架已建：WORKFLOW、REQUIREMENTS、DIRECTORY_STRUCTURE、DOCUMENTATION_MAP
- [ ] 决策记录位置已统一（不在两处同时放）
- [ ] 密钥/凭证已加密，明文不入库
- [ ] git初始化完成，首次提交已做，远程已关联（如需要）

## 六、项目建完之后

项目骨架建完后，后续怎么维护、新会话怎么接手、提交前检查什么，详见监控模块：
- **定规矩**（什么能自己定、什么情况要停）：[monitor.md](../monitor/monitor.md)
- **定操作**（信息放哪、提交检查、新窗口接手）：[maintenance-sop.md](../monitor/maintenance-sop.md)

### 硬约束（必须遵守）

- ❌ 不把API key、token、密码写进会入库的文件
- ❌ 不修改原始素材文件（只读）
- ❌ 不在两处同时放决策记录/状态台账
- ❌ 不删除用户已有文件，覆盖前先确认

---

## 反模式

- 总纲写一大段愿景，没有可量化成功标准 → 半年后无法判断做完没。
- 不数活跃项目数就开新坑 → 项目太多，全部停在半路。
- 调研底稿和最终报告塞一起 → 找结论要翻一堆文档。
