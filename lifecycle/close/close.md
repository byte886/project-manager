# 项目收尾与归档（Closing）

> **回答的问题**：项目做完了，或者决定不做了，怎么收尾才不留尾巴？
> **达到什么效果**：项目正式结束，交付物归档、资源释放、经验沉淀，不会"丢着不管、还在花钱"。

---

## 一、关闭不是"停止工作"

项目关闭不是"不做了"就完事。正式关闭要完成这些事（个人版六步）：

1. 交付物完成、移交
2. 写复盘总结（学到了什么）
3. 文档归档（让人看得懂发生了什么）
4. 更新台账状态
5. 释放资源（停掉订阅、服务、密钥）
6. 通知相关人（对外项目）

---

## 二、关闭步骤（SOP）

### 第1步：交付物移交
- 最终产出（报告/网站/数据/文档）放进 `01_结论与产出/`。
- 对外交付的（客户、读者），确认对方已收到。

### 第2步：写复盘总结
- 写一页"退役总结"（模板见第三节）。
- 必答三问：
  1. **什么让我意外？**（立项时没想到的事）
  2. **什么值得重复？**（下次可以照搬的做法）
  3. **下次怎么做？**（要改进的一点）

### 第3步：文档归档
- 项目移入归档目录或归档知识空间。
- **保持原结构**，不拆散、不删除——让人看得懂发生了什么。
- 退役不删除，只打"已归档"标签。

### 第4步：更新台账
- 项目状态改为 `Completed`（做完）或 `Cancelled`（砍掉）。
- 记录关闭日期。

### 第5步：释放资源（技术退役清单）
停掉和项目相关的、以后用不上的东西：

- [ ] 域名：停掉续费 / 转入停放
- [ ] 托管/云服务（如 Vercel、Cloudflare 等）：删除项目
- [ ] API token / 密钥：撤销
- [ ] 数据库：快照备份后删除
- [ ] 付费订阅/独立子账号：取消
- [ ] 定时任务、自动化：关闭

### 第6步：通知（对外项目）
- 对外服务（网站、公众号、App）发停止服务（EOL）公告。
- 告知协作者/客户项目正式结束、后续找谁。
- 关闭要**主动沟通**，不要假设别人知道。

---

## 三、退役总结模板（一页纸）

```markdown
# 退役总结 · <项目名>

> 退役日期：YYYY-MM-DD ｜ 结果：✅ 完成 / ⏸ 暂停 / ❌ 取消

## 1. 项目概况
- 目标：<一句话>
- 实际结果：<一句话>

## 2. 关键数据
- 投入时间：<X周 / Y小时>
- 产出：<交付物清单>
- 成果：<金钱 / 成长 / 数据指标>

## 3. 三问复盘
- 什么让我意外？<…>
- 什么值得重复？<…>
- 下次怎么做？<…>

## 4. 数据去向
- 保留在哪：<归档链接 / 本地路径>
- 已备份：<是/否>

## 5. 残留事项
- <域名/服务是否已停>
- <是否还有人依赖此项目>
```

---

## 四、归档 vs 删除原则

- **退役不删除**：完成/取消的项目**不删文档**，打"已归档"标签、移入归档目录。
- 保留历史可追溯——以后可能想回头看"当时为什么砍了这个项目"。
- **真正删除**只发生在：
  1. 有隐私/合规要求（如个人数据必须销毁）；
  2. 空间不够且已备份。
- 删除前必须确认：已备份 + 已写退役总结。

---

## 五、暂停 vs 终止（别搞混）

| 状态 | 含义 | 资源怎么处理 |
|---|---|---|
| **暂停 On Hold** | 以后可能继续，只是现在不做 | 保留，可暂时保留订阅/服务 |
| **终止 Cancelled** | 决定不做了，正式结束 | 按上面六步释放、归档 |

> 拿不准是暂停还是终止时，先标暂停；季度评审时再决定。

## 反模式

- 项目做完直接丢着 → 订阅还在扣费、域名还在续费。
- 砍项目不写复盘总结 → 以后重蹈覆辙。
- 退役就删除文档 → 想回看"当时为什么砍"时什么都没了。
