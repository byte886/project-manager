# close · 项目收尾

> 项目做完了，或者决定不做了。怎么正式结束？怎么不烂尾？怎么沉淀经验？

---

## 这个阶段回答什么问题

| 核心问题 | 通俗解释 |
|---|---|
| 怎么算正式结束？ | 该交付的交付、该停的停、该归档的归档 |
| 学到了什么？ | 复盘总结，经验沉淀下来 |

---

| 文件 | 作用 |
|---|---|
| `close.md` | 收尾SOP：收尾检查清单、正常完成流程、项目终止（砍掉）流程、复盘模板 |

## 你遇到什么，看哪里

| 你遇到什么情况 | 看哪里 |
|---|---|
| 项目做完了，要正式收尾、归档 | `close.md`（收尾Checklist章节） |
| 项目决定不做了（砍掉），要妥善结束 | `close.md`（项目终止流程章节） |
| 要写复盘总结，不知道写什么 | `close.md`（复盘模板章节） |
| 项目暂停（以后可能做），不知道怎么处理 | `close.md`（暂停 vs 终止的区别章节） |

---

## 收尾阶段核心产出

完成收尾后，你应该有：
1. ✅ 交付物全部完成、验收通过（正常完成时）
2. ✅ 该停的任务、该关的资源都处理了
3. ✅ 文档完整归档
4. ✅ 一份**复盘总结**（经验教训）
5. ✅ 项目状态改为 `Done`（完成）或 `Cancelled`（取消）

> 收尾是项目生命周期的最后一步，做好收尾，项目才算真正结束。
