# 活态台账（任务状态 + 问题）

> 项目有2条以上任务线时用，新窗口接手一句话知道到哪了。
> 达到什么效果：任何新会话读完就知道进度、下一步干啥、踩过什么坑，不用重新问"我们做到哪了"。

## 1. 任务状态台账
> 什么时候用：项目有2条以上任务线、需要"新窗口接手时一句话知道到哪了"时

## 模板本体

```markdown
# 任务状态台账（TASK_STATUS）

> **文档类型**：Active（全局活态台账，唯一进度真相）
> **更新频率**：阶段切换 / 工单状态变化 / 遇阻塞 / 每次 git 提交前
> **维护者**：AI 自动维护
> **读者**：AI 代理（每次启动 / 接手必读）+ 用户（看全局进度）

## 职责边界（先读）

- **这份文档装什么**：项目全局阶段进度、工单状态、下一步、跨会话必须先知道的硬约束。回答"**整个项目到哪了、接下来做什么**"。
- **谁在用**：AI 每次启动 / 接手 / 被问"现在做什么"时先读本文件；用户用它看全局。
- **什么时候写**：工单状态切换、里程碑完成、下一步发生变化时**立即更新**，不攒到"以后再说"。
- **绝不装什么（边界）**：
  - **不抄易变明细**：批次逐行进度、逐单元计数、日志、中间产物 → 留在对应工作区 / 工单档案，本文件只放一句话指针（数字以工作区实时为准）。
  - **不展开问题**：BUG / 坑的生命周期登记在 `ISSUES.md`；本文件只在状态行引用其编号（如"受阻，见 ISSUE-NNN"），不重复描述。
  - **不写稳定结论**：定了不改的决策 → `decisions/ADR-NNN`；跨会话稳定结论 → `memory/`，本文件只放指针。

> 最后更新：**YYYY-MM-DD（一句话最新进展）**。**当前阶段＝<现在主攻什么>。**

## 当前进度总览

| 阶段 | 状态 | 说明 |
|------|------|------|
| <阶段 1，如：基础站搭建> | ✅ 完成 | <一句话结论 + 指针> |
| <阶段 2，如：功能扩展> | 🔄 进行中 | <当前做到哪 + 指针> |
| <阶段 3，如：性能优化> | ⏳ 待启动 | <前置依赖是什么> |

状态标记：✅ 完成 | 🔄 进行中 | ⏳ 待启动 | ⏸️ 挂起 | ⚠️ 受阻 | ❌ 取消

## 进行中 / 待办工单

| 编号 | 标题 | 类型 | 状态 | 说明（指针级） |
|------|------|------|------|----------------|
| T-NN | <工单标题> | <功能/修复/文档/运维> | 待办 | <一句话 + 档案路径> |
| T-NN | <工单标题> | <类型> | 进行中 | <做到哪一步> |
| T-NN | <工单标题> | <类型> | 受阻 | <阻塞点 → 见 ISSUE-NNN> |
| T-NN | <工单标题> | <类型> | 挂起 | <为什么暂缓、等什么条件> |
| T-NN | <工单标题> | <类型> | 已完成 | <完成日期 + 产物指针> |

## 下一步（按优先级）

1. <下一步要做的第一件事，可判定>
2. <第二件事>
3. <第三件事>

## 关键口径（指针，不展开）

- <一句话结论> → 权威源 `<路径或 ADR-NNN>`
- <一句话结论> → 权威源 `<路径或 ISSUE-NNN>`

## 最近完成（倒序）

### YYYY-MM-DD

- ✅ <做了什么>：<产物路径>，<关键数字 / 验收结果>
- 🔧 <修了什么>：<产物路径>，<根因指针 ISSUE-NNN>
- 📝 <补了什么文档>：<产物路径>

### YYYY-MM-DD

- ✅ <做了什么>：<产物路径>，<关键数字>

*最后更新：YYYY-MM-DD*
```

## 什么时候**不**用这个模板

- 只有一条任务线、做一次就结束的短任务——工单档案（task-brief）就够，不用全局台账
- 进度本身就是数据（如数据库里的 issue 系统）——别在 markdown 里抄第二份，指针指向系统即可
- 已关闭的历史项目——把本文件归档进 `reviews/`，不要再更新

## 2. 问题台账
> 什么时候用：项目里踩过'下次换个任务还会踩'的机制级坑时

## 模板本体

```markdown
# 问题台账（ISSUES）

> **文档类型**：Active（活态台账）
> **更新频率**：机制级问题发现 / 解决时
> **维护者**：AI 自动维护 + 用户审核
> **读者**：AI（排障前先查）+ 用户（看遗留风险）

## 职责边界（先读）

- **这份文档装什么**：**换个任务还会踩的机制级问题**（工具链、流程、架构、环境层面的坑）及其 open → closed 生命周期。回答"**这个项目有哪些共性的坑、怎么解的**"。
- **谁在用**：AI 动手排障前、被问"有什么 bug / 有什么坑"时读本文件；修复后回填解法。
- **什么时候写**：发现影响**不止一个工单**、或属于工具链 / 流程 / 环境本身的缺陷时登记。
- **绝不装什么（边界）**：
  - **一次性小 bug 不进**（某条数据格式错、某次接口偶发失败）→ 记在对应工单档案 `active/<task>.md`；只有判定"换个任务还会踩"才提升到这里。
  - **当天易变的报错日志不登记**（看运行日志即可）。
  - **任务进度不写在这里** → 那是 `TASK_STATUS.md` 的事，本文件只记问题本身。

---

- **修复方案**：<打算怎么修，分几步>
- **验证**：<怎么算修好——给定 X 应得到 Y，用不同于生成路径的方式回读>

## 维护规则

1. **必须记录**：发现机制级问题时必须登记，不能只在对话里提一句。
2. **解决后移区不删号**：修好后从"开放"移到"已解决"，编号永久保留、不复用。
3. **保留最近 N 条**（建议 10 条）：更早的若有长期价值，提炼成 ADR 或 memory concept 后从这里淡出。
4. **AI 排障先查这里**：动手前先 grep 本文件，确认不是已知坑，避免重复试死路。
```

```markdown
## 开放问题

### ISSUE-001: Node 22 下 ESM 加载 data/*.json 报错 🔴

- **状态**：待执行（2026-10-08）
- **发现时间**：2026-10-07
- **问题描述**：本机 `nvm use 22` 后 `pnpm dev` 启动即报 `ERR_IMPORT_ASSERTION_TYPE_MISSING`，构建 `pnpm build` 失败；换 Node 20 后正常。
- **根因**：Next.js 项目以 ESM 方式直接 import `data/books.json`，Node 22 要求显式 import assertion；Node 20 宽松放行。
- **修复方案**：① `.nvmrc` 锁 20.x 并写进 AGENTS.md §3.6；② 长期改成 `fs.readFile` 读 JSON，去掉 import assertion 依赖（排在 T-04 之后）。
- **验证**：`nvm use` 切到 22 时应报明确的"不支持 Node 22"提示而不是堆栈；切回 20 后 `pnpm build` 0 错误。

### ISSUE-002: Vercel 生产构建 504 超时 🟡

- **状态**：研究中（2026-10-08）
- **发现时间**：2026-10-08
- **问题描述**：推送后 Vercel 构建 60s 超时失败；本地 `pnpm build` 只要 8s。
- **根因**：待定位——怀疑 `data/books.json` 200 本 × 封面元数据在构建期同步处理拖慢，未证实。
- **修复方案**：先本地用 `NODE_ENV=production pnpm build` 复现，加构建耗时日志；不行就把封面元数据改客户端读取。
- **验证**：Vercel 构建 <60s 通过；产物里首屏数据不再构建期处理。

优先级：🔴 高（阻塞核心流程 / 数据丢失 / 安全）→ 立即处理；🟡 中（效率 / 功能受限）→ 计划处理；🟢 低（体验优化）→ 后续维护。

## 已解决问题（最近 10 条，更早的提炼进 ADR / memory 后淡出）

### ISSUE-003: `pnpm install` 后页面样式丢失

- **解决时间**：2026-09-28
- **问题描述**：新装依赖后 Tailwind 类名全失效，页面无样式。
- **根因**：混用了一次 `npm install`，生成了 `package-lock.json`，与 `pnpm-lock.yaml` 版本树不一致，Tailwind JIT 扫到了错误的依赖版本。
- **结果**：删 `package-lock.json` + `node_modules`，`pnpm install` 重装恢复；AGENTS.md §3.6 加"只用 pnpm"硬规则。
- **通用教训**：**lockfile 出现第二份包管理器文件就是红旗**——样式 / 行为异常先查 `ls package-*.json pnpm-lock.yaml yarn.lock`，不是查代码。

### ISSUE-004: 详情页 404——slug 含中文导致 URL 编码不一致

- **解决时间**：2026-09-25
- **问题描述**：部分中文书名详情页 404，英文书名正常。
- **根因**：`slug` 直接用了中文书名，Next.js 动态路由对未编码中文路径处理不一致；`data/books.json` 里存的 slug 又是手动写的，同一本书两个地方对不上。
- **结果**：统一规则——slug 一律拼音 / 英文 kebab-case（如 `three-body`），书名只做显示字段；写了个 `scripts/check-slug.mjs` 在 build 前校验唯一性。
- **通用教训**：**URL 里的标识字段永远不用自然语言**——中文 / 空格 / 标点都是定时炸弹；标识字段单独存，显示字段随便改。
```

## 什么时候**不**用这个模板

- 一次性任务里的偶发报错（这次接口挂了、这张图传失败）——修完就完了，不进台账
