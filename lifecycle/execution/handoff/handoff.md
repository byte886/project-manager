# 项目活日志交接（HANDOFF）

> **什么时候用**：项目进行中，需要一份"这一路怎么讨论过来的、为什么这么决策、现在卡在哪"的活文档；新 AI 窗口接手时第一时间读它进入上下文。不是一次性交接快照——每轮重要讨论都往里追加。
> **怎么用**：整段复制模板本体到 `docs/HANDOFF.md`。§0 30 秒画像填 5 个 bullet；§1 倒序日志每条按"聊了什么→结论→为什么"三段写，最新永远在最上面；§2 关键决策只放指针不复制论证；§3 当前纠结分五类标清楚。**纪律：定稿结论编译进 ADR/memory，本文件不长期堆结论；易变数字只放台账。**
> **达到什么效果**：新窗口 30 秒知道项目是什么、做到哪；翻 §1 倒序日志知道每个决策背后的理由（ADR 只留结论，这里留为什么）；翻 §3 知道哪些等用户拍板、哪些 AI 自己能做，不用追问"现在什么情况"。

## 填好的示例（虚构项目：个人读书清单站 bookshelf）

```markdown
# 项目日志与交接（HANDOFF）

> 这是一份**活的项目日志 + 需求同步**，不是一次性交接快照。
> **读者**：新接手的 AI 窗口。回答：这一路怎么讨论过来的？为什么这么决策？现在卡在哪？
> **维护**：每轮重要讨论往 §1 倒序追加；§3 随进度更新。定稿结论编译进 ADR/memory，本文件不长期堆结论。

---

## 0. 30 秒画像

- **是什么**：个人读书清单静态站，记录读过的书，Next.js + JSON 数据 + Vercel 部署。
- **北极星**：零后端、零数据库，打开就能看到自己读过的书，搜索和标签筛选好用。
- **当前主战场**：列表页加标签筛选功能。
- **现在在**：搜索已经上了 fuse.js 跑通；标签筛选刚做完前端过滤，URL 同步还没做；标签筛选功能还没上线。
- **仓库**：本地 `~/projects/bookshelf`；GitHub `github.com/byte886/bookshelf`（public，main 分支）。

---

## 1. 项目日志（倒序，最新在上）

### 2026-10-08 · 标签筛选前端方案 + URL 同步待定
- **聊了什么**：标签筛选是前端内存过滤还是预生成页面？筛选状态要不要同步到 URL？
- **结论**：①前端在内存里 `books.filter(b => b.tags.includes(tag))`，不预生成页面；②URL 同步 `?tag=xxx`，刷新后保留筛选；③先用无痕窗口验证，不信自己浏览器缓存。
- **为什么 / 残留**：200 本书数据量小，内存过滤 <50ms 完全够；URL 同步是为了能分享带筛选条件的链接。残留：URL 同步还没写，今天先把过滤逻辑跑通。

### 2026-10-06 · 搜索方案选 fuse.js 不选 Lunr
- **聊了什么**：站内搜索用什么库？Lunr 要预建索引、fuse.js 纯前端 fuzzy，哪个合适？
- **结论**：上 fuse.js。
- **为什么 / 残留**：200 本书量级，fuse.js 零构建步骤、开箱即用；Lunr 需要构建时生成 index，对静态站反而多一步。实测 fuse.js 搜索"三体"能匹配到"三体 II：黑暗森林"。已否决 Lunr，见 ADR-002。

### 2026-10-05 · 数据存储选 JSON 文件不上数据库
- **聊了什么**：书单数据存哪？JSON 文件 / SQLite / Notion API？
- **结论**：全部存 `data/books.json`，跟着 Git 走，构建时打包进静态产物。
- **为什么 / 残留**：试过 Notion API，构建时拉取要 3-5 秒且限流不稳定；JSON 可 git diff、可回滚、Vercel 零配置。负面代价：超过 2000 本时按年份拆文件（届时再说）。详见 ADR-003。

| 技术栈 Next.js + Vercel | `project-management/decisions/ADR-001-技术栈选型.md` |

## 3. 当前纠结 / 待拍板

- **AI 可独立做**：标签筛选的 URL 同步（`?tag=xxx`）、筛选按钮 UI 样式微调。
- **待用户拍板**：标签筛选做完后，要不要加"多选标签"（OR 还是 AND 逻辑）？AI 推荐先做单选，多选等 500 本以后再说。
- **待人工触发**：部署到 Vercel 需要用户点确认，不自动推。
- **暂缓项**：导出 CSV 功能（用户说先把标签筛选做了再说）。
- **诚实的局限**：标签筛选还没在无痕窗口验证过；中文标签的跨词误匹配问题（"计算机"匹配到"计算"）还没复现确认。
```

## 什么时候**不**用 HANDOFF

- 项目刚启动、还没有任何讨论和决策——等第一次重要讨论后再建
- 一次性任务（写个脚本跑一次就完）——不需要活日志，task-brief 够了
- 纯研究 / 调研项目（没有持续推进的代码）——research 文档本身就是交付物
