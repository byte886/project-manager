# 交接SOP

> 上下文太长要开新窗口、要把一个子任务交给另一个AI。

## 1. 新窗口接手SOP
> 什么时候用：上下文太长要开新窗口/换机器

## 模板本体

```markdown
# 新窗口怎么接手这个项目（开新任务窗口 · 固定 SOP）

> 目标：**只要知道仓库位置，新窗口就能接手**，不需要老窗口复述背景。
> 冷启动读什么、什么顺序、红线、验收题，全部由仓库里的 `<AGENTS.md>` 冷启动章节与 `<项目维护SOP>` 冷启动六问接管。

---

## 0. 触发词（听到就走本 SOP，不自创交接长文）

用户说任一句："上下文有点大了，开个新任务窗口" / "换新窗口" / "新窗口接手" / "再开个窗口接着干" / "开个新任务接手"，当前窗口（=**老窗口**）立即按 §1 收口。

---

## 1. 老窗口收口（开窗之前，AI 做，四步）

1. **状态落盘**：本轮重要讨论/决策往 `<docs/HANDOFF.md>` §1 **倒序追加一条**（最新在上）；`<TASK_STATUS.md>`、`<ISSUES.md>` 更新到最新（易变进度只留台账）。
2. **体检**：仓库根跑 `<体检命令>`，必须 **0 ERROR**（WARN 记录后可放行）。
3. **提交并推送**：`git add -A && git commit -m "<写清做了什么>" && git push origin <分支名>`。
4. **发操作指引**：把 §2 的两步和标准句**原样**发给用户，不再写长篇交接段落（仓库自描述，结论都在仓里）。

---

## 2. 用户开窗两步（本机，最简）

1. 新建任务窗口时，**项目文件夹选成 `<仓库绝对路径>`**
   （不要用系统默认的聊天临时目录——那里的 AGENTS.md 是旧的或缺失，会误导新窗口）。
   作用：定位仓库、工作目录落在项目里；**但不保证规则自动注入**，所以第 2 步不能省。
2. **只发这一句（标准句，原文照发）**：

   ```
   接手这个项目，按 AGENTS.md 冷启动章节读，先把 <项目维护SOP> 的冷启动六问答给我听，再等我派活。
   ```

   短句"按 AGENTS 冷启动答六问"语义等价、同样有效。

---

## 3. 新窗口验收（怎么算接手成功）

- 新窗口应**不翻旧聊天**就答出冷启动六问（①项目是什么 ②走到哪/最近完成什么 ③下一步/待拍板 ④开放问题/坑 ⑤红线 ⑥关键命令），清单原文见 `<项目维护SOP>`。
- 老窗口可让新窗口把六问答出来，抽查 1~2 条与 `<TASK_STATUS.md>` 对得上。
- 答不上、或文档自相矛盾 → **不开工**，先按 `<项目维护SOP>` 修文档（说明仓库自描述有缺口）。

---

## 4. 兜底（换机 / 网页版 / 无法选项目文件夹）

- **新机器先 clone**：`git clone <仓库地址>`，再把文件夹选成克隆目录，其余同 §2。
- 没法让系统读到项目 `AGENTS.md` 时，复制下面整段发给新窗口（已带仓库路径与阅读顺序）：

   ```
   接手一个进行中的项目，仓库在 <仓库绝对路径>
   （GitHub: <仓库地址>，<public/private>，<分支名> 分支）。
   这是"<一句话项目定位>"。

   请严格按仓库根 AGENTS.md 冷启动章节恢复，不要凭文件名猜测、不要直接写代码，按顺序读：
   1. AGENTS.md → 2. README.md → 3. <docs/DOCUMENTATION_MAP.md> → 4. <docs/WORKFLOW.md>
   → 5. <docs/HANDOFF.md>（§1 倒序日志 + §3 当前纠结）→ 6. <project-management/active/TASK_STATUS.md>
   → 7. <project-management/active/ISSUES.md> → 8. 按当前任务读对应 guides/research。
   读完用 <项目维护SOP> 的冷启动六问自测，并把六个答案讲给我听：
   项目是什么、走到哪最近完成什么、下一步与待我拍板项及你的推荐、
   开放问题与已知坑、红线、关键命令。六问答不上来先修文档再动手。

   红线：<列 3-5 条本项目最关键的红线，比如什么不能入库、什么必须人工确认、什么命令不能用>。
   提交前必须 <体检命令> 0 ERROR。需要凭证或权限先问我。
   现在请先完成冷启动并汇报六问，再等我布置具体任务。
   ```

---

## 为什么至少还要"选文件夹 / 给路径"这一步

新对话默认不知道你要接手**哪个**项目（本机不止一个项目），所以"告诉它仓库在哪"省不掉——这本身就是"只需知道仓库位置"。位置一旦给了，**读什么、什么顺序、答哪六问、红线是什么，全部由仓库里的 AGENTS.md / 项目维护SOP / HANDOFF / 台账接管**；标准句再强制一次冷启动，不依赖自动注入是否生效，不需要解释任何来龙去脉。
```

## 什么时候**不**用这个 SOP

- 项目还没建完治理体系（没有 AGENTS.md、没有 TASK_STATUS、没有 HANDOFF）——先把基础设施搭起来再谈交接
- 第一次启动一个全新项目——没有"接手"一说，直接按项目启动流程走
- 不需要跨窗口/跨会话，同一个窗口一直干到底——不用走这套 SOP

## 填好的示例（虚构项目：个人读书清单站 bookshelf）

```markdown
> 更新：2026-10-08 19:30 ｜ 状态：进行中
> 仓库：~/projects/bookshelf
> Remote：git@github.com:byte886/bookshelf.git
> HEAD：a1b2c3d

## 0. 给接手方的提示词（可直接粘贴到新对话）

> 你在 `~/projects/bookshelf` 工作。先读 `AGENTS.md` 和本文件。
> 目标：给书单加"按标签筛选"功能。
> 硬约束：不引入数据库，继续用 JSON 静态文件；不改动现有详情页 URL。
> 禁止重试：本文件第 4 节列的死路，不要重试。
> 允许人工配合：部署到 Vercel 需要你点确认，不要自己推。
> 现在请先读完本文件，复述你理解的目标和死路，再动手。

## 1. 项目总目标与本任务定位

bookshelf 是一个静态站，记录读过的书，目前 200 本，有搜索和详情页。
本任务 = 在列表页加标签筛选，与"导出 CSV"那条线解耦。

## 2. 硬约束（不可违反）

- 不引入数据库 / 后端，继续用 `data/books.json`
- 详情页 URL 格式 `/books/<slug>` 不许变
- 标签数据从书的 `tags` 数组读，不新增字段

## 3. 已验证闭环（直接复用，勿重做）

### 3.1 搜索
- 入口：`components/SearchBox.tsx`
- 已跑通：前端 fuzzy 匹配，200 本 < 50ms
- 不要重做：上了 fuse.js，够用，别换 Lunr

## 4. 已验证死路（禁止重试，附证据）

| # | 方向 | 结论 / 证据 |
|---|---|---|
| 1 | 用 RSS 订阅标签页 | 这是纯静态站无服务端，RSS 需要构建时生成，200 本标签组合爆炸，上一版试过渲染 40 分钟超时（见 HANDOFF 2026-09-20 条目） |
| 2 | 把 tags 拼成字符串做 indexOf 过滤 | 中文标签会跨词误匹配（"计算机"匹配到"计算"），已在 ISSUE-007 复现 |

## 5. 关键技术资产与 ID

- 数据：`data/books.json`，每本 `{slug, title, author, tags[], rating}`
- 构建命令：`pnpm dev` / `pnpm build`
- Node 20，不要用 Node 22（ESM 加载 .json 有 bug）

## 6. 下一步主攻

### 原理
前端在内存里按 tags 数组过滤 books 即可，不用预生成页面。

### 步骤
1. 先在浏览器 Console 里对 books.json 跑一遍 `books.filter(b => b.tags.includes('科幻'))`，确认数据结构
2. 在列表页加标签按钮组，点击时 setState 过滤
3. URL 同步 `?tag=科幻`，刷新后保留筛选

### 验证标准
- 点"科幻"按钮，列表只剩 tags 含"科幻"的书；URL 出现 `?tag=科幻`；复制 URL 到无痕窗口能复现
- 用无痕窗口回读（不是你自己浏览器的缓存）

## 7. 落盘与目录规范
- 组件放 `components/TagFilter.tsx`
- 测试放 `tests/tag-filter.test.ts`

## 8. 参考资料
- [URLSearchParams MDN](https://developer.mozilla.org/en-US/docs/Web/API/URLSearchParams)

## 9. 验收清单
- [ ] 点标签按钮列表正确过滤
- [ ] URL 同步且刷新保留
- [ ] 无痕窗口打开带 tag 的 URL 复现筛选结果
- [ ] `pnpm build` 无报错
```
