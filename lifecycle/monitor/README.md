# monitor · 项目监控与维护

> 项目开工后怎么管？怎么避免文档打架？怎么定期检查？

---

## 两个文件的分工

| 文件 | 回答什么问题 | 通俗理解 |
|---|---|---|
| `monitor.md` | 我能决定什么？什么情况必须停下来？多久检查一次？ | **定规矩**：项目治理的方法论 |
| `maintenance-sop.md` | 各类信息该放哪？提交前检查什么？新窗口怎么接手？ | **定操作**：具体怎么维护项目 |

---

## 你遇到什么，用哪个

| 你遇到什么情况 | 看哪个文件 |
|---|---|
| 项目刚开工，想定清楚"什么事自己能定、什么情况要停" | `monitor.md` |
| 想建立"一条信息只放一处"的规则，避免文档互相矛盾 | `maintenance-sop.md` |
| 每周要自查项目，不知道检查什么 | `monitor.md`（每周15分钟自查章节） |
| 准备提交，怕漏改文档、怕提交不该提交的东西 | `maintenance-sop.md`（提交前检查清单） |
| 开新窗口/换AI，要让新会话快速接手项目 | `maintenance-sop.md`（新窗口接手六问） |
| 要记录重要决策，不知道怎么写 | `monitor.md`（关键决策记录章节） |

## 核心概念速记

### 项目监控管3件事
1. **决策权**：什么自己能定
2. **暂停条件**：什么情况必须停
3. **检查节奏**：多久检查一次

### 项目维护核心原则
**一条信息只放一处**：
- 每类信息一个权威位置
- 其他地方只放链接，不复制
- 避免改漏、避免说法打架
