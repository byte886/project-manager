# 项目监控：开工后怎么管

> **回答的问题**：项目开工后，我能自己决定什么？什么情况必须停下来？多久检查一次？
> **什么时候用**：项目已经启动，进入执行阶段后。

---

## 一、项目监控到底管什么（3件事）

项目监控听起来很复杂，其实就管3件事：

| 事情 | 通俗解释 | 例子 |
|---|---|---|
| **1. 决策权** | 什么事你自己能定，什么事要停下来想清楚 | 小调整自己定，改目标要停下来 |
| **2. 暂停条件** | 踩到什么线就必须停下来，不能继续闷头干 | 进度晚了2周、钱超了20% |
| **3. 检查节奏** | 多久花点时间检查一次 | 每周15分钟自查 |

### 为什么要定这些规则？

不是为了管自己，而是为了：
- 避免"做着做着跑偏了，半年后才发现"
- 避免"什么事都凭感觉，真出问题时不知道怎么办"
- 让项目有明确的"什么时候继续、什么时候停下来"

---

## 二、一个人怎么管（简化版）

团队项目有很多角色和会议，一个人干可以简化：

```
你一个人 = 干活的人 + 拍板的人
"升级" = 停下来，把项目挂起，重新想想要不要继续
```

不用开评审会，不用写复杂报告，但是**必须写清楚"什么情况要停下来"**。

### 3个核心原则

1. **看结果，不看忙不忙**：
   - 不问"这周写了多少文档、加了多少班"
   - 问"目标推进了吗？假设验证了吗？"

2. **少控制，多自查**：
   - 不用每天写进度报告
   - 每周花15分钟自己检查一次就够

3. **计划错了就改**：
   - 不要硬撑着按错误的计划走到底
   - 发现不对就调整，调整要记录原因

## 三、项目治理卡模板（一页纸）

> 每个项目写一张，放在决策记录目录下（`02_决策记录/治理卡.md`）。
> 写清楚：你能决定什么、什么情况要停、多久检查一次。

```markdown
# 治理卡 · <项目名>

> 最后更新：YYYY-MM-DD

## 基本信息
- 目标：<一句话说清项目要完成什么>
- 截止日期：YYYY-MM-DD
- 负责人：<我>

## 我可以自己决定的范围
- 小调整：不改变项目目标和成功标准的调整，可以自己定
- 花钱：单笔 ≤ <金额> 或 累计 ≤ <金额> 以内，可以自己定
- 时间：不影响关键里程碑的进度微调，可以自己定

## 什么情况必须停下来（命中任意一条就停）
- [ ] 进度比计划晚了 > 2周
- [ ] 花费超了 > 20%
- [ ] 出现新情况，让项目立项时的核心假设不成立了
- [ ] <项目特有的情况，比如：关键渠道不能用了、政策变了、合作方取消>

## 多久检查一次
- 每周15分钟自查：范围还对吗？进度走得动吗？有新风险吗？
- 每季度批量评审所有项目
- 关键节点：立项 / 阶段验证 / 发布

## 停下来之后怎么办
1. 命中暂停条件 → 把项目状态改为"挂起"（On Hold）
2. 写一句"为什么暂停"
3. 下次评审时决定：继续 / 调整后继续 / 暂停 / 终止
```

## 四、关键决策要记录

重要决策不要只放在脑子里，半年后会忘。写下来"当时为什么这么选"。

### 什么时候要写决策记录？

- 选了技术栈/工具/平台
- 砍了一个原计划要做的功能
- 改了截止日期或成功标准
- 预算/资源重新分配
- **不用**为日常小选择写（浪费时间）

### 决策记录模板

```markdown
# 决策记录 #NN · <一句话说决策是什么>

- 日期：YYYY-MM-DD
- 项目：<项目名>
- 状态：已接受 / 被 #XX 取代

## 当时面对什么问题
<当时的情况、约束、压力>

## 最后选了什么
<决策内容>

## 放弃了哪些备选方案
- 方案A：<是什么>，放弃因为 <原因>
- 方案B：<是什么>，放弃因为 <原因>

## 这个决策的代价，什么时候该重新考虑
<有什么影响、什么情况下要推翻>
```

## 五、每周15分钟自查

每周固定一个时间（比如周日晚上），对每个活跃项目问3个问题：

| 问题 | 检查什么 |
|---|---|
| **1. 范围还对吗？** | 这周做的事还在往目标走吗？还是跑偏成了"为做而做"？ |
| **2. 进度走得动吗？** | 离里程碑还有多远？有没有晚 > 2周？ |
| **3. 有新风险吗？** | 有没有新情况让原来的假设不成立？ |

### 答完之后
- 全部正常 → 继续
- 有黄灯（有风险但不严重）→ 更新状态，下周重点补救
- 命中暂停条件 → 挂起项目，等评审

## 六、风险登记（简单版）

中大型项目可以用，小项目不用。

```markdown
# 风险清单 · <项目名>（每周自查时更新）

| 风险是什么 | 发生概率（1-5） | 影响程度（1-5） | 怎么应对 | 状态 |
|---|---|---|---|---|
| <比如：新渠道获客慢> | 4 | 3 | 先做10篇内容测试，等4周看数据 | 监控中 |
```

---

## 反模式（不要这么做）

- 不写治理规则，靠"到时候再说" → 真出问题时凭感觉硬扛。
- 暂停条件写得模糊（"感觉不对就停"）→ 永远不会触发。
- 重要决策只在聊天记录里 → 换个会话就失忆，以后重复踩坑。
